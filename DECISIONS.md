# Decisions

- Laravel 13.42 (latest stable) + Breeze 2.4 `livewire-functional` stack with Pest — Breeze still installs cleanly on L13.
- Removed skeleton `CLAUDE.md`/`AGENTS.md` (Laravel Boost agent prompts) — they ask to install Boost, an extra dependency not in the stack.
- `config('app.timezone')` stays `UTC` so Eloquent stores UTC; `APP_TIMEZONE=Asia/Ho_Chi_Minh` feeds a separate `app.display_timezone` used for parsing bank times and rendering — satisfies "store UTC, display HCM".
- Default locale `vi`, fallback `en`.
- `mail_accounts.app_password` is nullable: "disconnect" wipes the password but keeps the row (status `disabled`) so transactions/raw emails keep their FK.
- `raw_emails.mail_account_id` is nullable: `thuchi:import-eml` creates raw emails without any mail account.
- Default categories are seeded from a `User::created` model hook, so every user (registration, factories, demo) gets them.
- PHP backed enums for direction/status/type/match_field; DB columns stay `enum(...)` as specced.
- Policies are plain owner checks (`user_id`) for view/update/delete; auto-discovered by naming convention.
- Added unique(user_id, match_field, match_value) on category_rules so "create or update a rule" is an upsert.
- MoneyParser returns a signed int (sign carries direction); a trailing separator followed by 1–2 digits is a decimal fraction (rounded half-up), otherwise every `.`/`,`/space is a thousands separator. VND never has 3-digit fractions.
- DateParser returns CarbonImmutable in the display timezone; callers must `->utc()` before saving because Eloquent does not convert timezones on write.
- Unit tests extend the Laravel TestCase (no DB) so `config()` works.
- No `samples/` directory existed → all fixtures are synthetic, generated as real MIME (.eml with 8bit / quoted-printable / base64 parts) so the MIME decoding path is exercised.
- `config/banks.php` also holds the parser class per bank; `ParserRegistry::fromConfig()` builds from it, so adding a bank = config entry + parser class.
- Shared logic lives in `AbstractBankParser` (label-based field extraction, sign/keyword direction, fallback date). Emails mentioning OTP/khuyến mãi/ưu đãi, or without an amount field, return null.
- Error-case parsing (amount_missing, direction_unknown) is tested inline rather than as fixtures, so `parse-stats` over imported fixtures can show 100%.
- `.eml` reading reuses `Webklex\PHPIMAP\Message::fromString` (same code path as live IMAP) via `FetchedMessage::fromEml`.
- Fixture folders use the uppercase bank code (`tests/Fixtures/emails/VCB`).
- Mailbox: `webklex/php-imap` (not the Laravel wrapper) — we build the client config ourselves, so no extra config file.
- `MailboxConnectionException` added next to `InvalidCredentialsException`: network/TLS failures must not flip the account to `needs_reconnect`; the job records `connection_failed` and rethrows so the queue retries (tries=2).
- Any non-connection failure during IMAP login is treated as invalid credentials; our exceptions never wrap Webklex's (their traces hold the password). `$appPassword` params carry `#[\SensitiveParameter]`.
- All Mail folder lookup tries `[Gmail]/All Mail`, `[Google Mail]/All Mail`, `[Gmail]/Tất cả thư`, then `INBOX` (Webklex doesn't expose the `\All` special-use flag).
- SyncMailAccount also drops any fetched message whose sender isn't configured (defense in depth on top of IMAP SEARCH FROM).
- `last_error` stores short codes (`invalid_credentials`, `connection_failed`); the UI translates them.
- `thuchi:sync` runs the sync inline (dispatchSync) — "runs a sync now"; the scheduler queues jobs instead.
- `thuchi:import-eml` and `thuchi:reparse` parse inline (dispatchSync) so the CLI shows results immediately; import skips files from unsupported senders.
- Reparse uses `updateOrCreate` on raw_email_id, keeping category and note.
- Category rules: counterparty rules = exact normalized match; description rules = normalized substring. Counterparty rules first. When a transaction has no counterparty, "remember" creates a description rule from its full description.
- Breeze tests adjusted for the new routing (log why, per rule 4): "navigation menu can be rendered" now loads `/settings` (the `/` page redirects users without a mailbox to `/connect`), and the example test asserts guests are redirected from `/` to `/login` (no public welcome page).
- `/` is the transactions page (route `transactions`); Breeze's `dashboard` route and welcome page were removed and all redirects point at `transactions`.
- The "no mail account → /connect" redirect also lets through users who have imported raw emails, so the demo user (imported via `thuchi:import-eml`, no Gmail) can explore the app.
- One mail account per user in the MVP: connecting again (same or different Gmail) updates the existing row; a new address resets `last_synced_at` so the first sync looks back 30 days.
- Connect form: the password is moved into a local variable and the public property cleared as the very first step, so it never round-trips in the Livewire snapshot, even on validation errors. App password format check is a hand-written regex error (no value echo).
- Language preference lives in the session (`SetLocale` middleware), not a DB column.
- UI copy uses Vietnamese strings as translation keys (`__('Giao dịch')`) with `lang/en.json`; Breeze's English strings are translated in `lang/vi.json`. `lang/vi/validation.php` covers only the rules we use; others fall back to English.
- Transaction detail is a full page (`/transactions/{id}`), not a bottom sheet — simpler and linkable.
- Reports chart is pure CSS bars (no Chart.js dependency).
- Dropped Breeze's Bunny Fonts link: system font stack, no third-party requests (privacy + offline PWA).
- PWA icon is a single SVG (`sizes: any`); no PNG generation tooling needed.
- "Xóa toàn bộ dữ liệu" reuses Breeze's password-confirmed delete-user form (FK cascades remove all data).
- DemoSeeder deletes and recreates demo@thuchi.test, pre-creates 6 category rules, then runs `thuchi:import-eml` over all fixtures (rules apply in the real pipeline). DatabaseSeeder dropped `WithoutModelEvents` so seeded users get default categories.
- VCB receipts (real samples, 2026-11-12): stacked "Vietnamese label / English label / value" blocks parsed with `AbstractBankParser::blockField()`. Receipts are always outgoing (sent from the user's "Tài khoản nguồn / Debit Account"); there's no balance line. Fees ("Số tiền phí") were 0 in all 47 samples and are ignored. If a non-zero fee shows up, decide whether it belongs in `amount`.
- Removed the synthetic VCB `01_transfer_out` fixture: it invented a layout for the real "Biên lai chuyển tiền" subject. Real samples are the source of truth.
- Real fixtures are redacted (owner name → NGUYEN VAN AN, account/phone/order numbers → fake, beneficiary names → fake, synthetic Message-IDs), and checked with a grep for any original identifiers.
- Migrations now have `down()` methods (owner's explicit request, overriding the global "up only" guideline): `migrate:refresh` without them silently skipped our tables, then dropping `users` cascaded the data away under SQLite foreign keys and left the schema half-migrated.
